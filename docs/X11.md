# AnWind 内置 X11 桌面（v2.22.2）

AnWind 现在自带 X11 显示端：在终端里一条命令即可把图形化 Linux 桌面
（xfce4 / openbox 等）投射为 **AnWind 桌面内的一个窗口**（fix9.6 起）
——窗口可自由拖拽/缩放/最大化/一键真全屏，分辨率可跟随窗口或固定；
不嵌入终端界面，也不抢占整屏。实现方法参考
[jiaxinchen-max/termux-app](https://github.com/jiaxinchen-max/termux-app)
的内置 X11 方案（基于 termux-x11 上游：lorie 合成器 + Xwayland 内嵌库），
并按 AnWind 的包名/前缀/桌面形态做了适配。

## 一、工作原理

```
AnWind 终端                        AnWind App 进程
────────────                       ─────────────────────────────
$ anwind-x11 :1
  └─ termux-x11 脚本
       CLASSPATH=宿主 APK
       app_process →
         CmdEntryPoint.main()
           native start():
             lorie + Xwayland
             （X server 运行在
              终端侧子进程）
           每秒广播 ACTION_START
           （binder 携带连接 fd）──→  AnWindApp 动态接收器
                                        └─ 拉起全屏 X11 桌面
                                           Activity（不进终端界面）
                                           └─ 从重播取 binder →
                                              getXConnection(fd) →
                                              LorieView 渲染
$ env DISPLAY=:1 startxfce4   ──→   X 屏幕尺寸 = 视图尺寸（自动调节）
```

- **X server 端**：`libXlorie.so`（四 ABI 预编译）随 APK 分发，由
  `app_process` 在终端侧子进程加载运行，X11 socket 落在 AnWind 自身
  的 `usr/tmp`，终端里的 X 程序直接 `DISPLAY=:1` 连接，无需任何代理。
- **显示端**（fix9.6）：`X11Surface` 把 `LorieView`（SurfaceView）
  嵌入 AnWind 桌面窗口（`X11WindowController` 完成广播→开窗→取
  fd→连接），画面随窗口自由拖拽/缩放/全屏；独立全屏 Activity
  （`com.termux.x11.MainActivity`）保留作兼容兜底入口。
- **输入**：直触模式（触摸点按 视图→X 屏幕比例直注）+ 软键盘开关
  （窗口控制条）；外接键鼠/手柄映射/扩展按键条沿用上游能力。
- **分辨率自适应**：`displayResolutionMode` 默认 `native`，X 屏幕尺寸
  实时跟随视图尺寸（旋转/全屏切换即时调整 X11 RANDR）；窗口控制条
  可随时切换为固定分辨率（如 1280x720）。

## 二、与 X11 应用不冲突

| 维度 | AnWind 内置 | 官方 Termux:X11 应用 |
|------|------------|---------------------|
| 宿主包名 | com.anwind | com.termux |
| 广播目标 | `TERMUX_X11_OVERRIDE_PACKAGE=com.anwind` | com.termux |
| X11 socket | com.anwind 的 tmp | com.termux 的 tmp |
| 进程名 | `anwindx11` | `com.termux.x11` |
| 显示号 | 默认 `:1`（可用 `:0`/`:2`…） | 任意 |

两者可同时安装、同时运行，互不干扰。

## 三、使用

```sh
# 0. 体检（可选，查看组件/依赖是否就绪，缺什么给什么命令）
anwind-x11 doctor

# 1. 安装桌面环境（首次；只有这一步需要 pkg，X 服务本体无需装任何包）
pkg update && pkg install x11-repo && pkg install xfce4 dbus

# 2. 启动（AnWind 桌面自动弹出 X11 窗口并拉起 xfce4）
anwind-x11

# 或指定显示号 / 只跑单个程序
anwind-x11 :1
anwind-x11 :1 xterm

# 手动启动会话请带 dbus-launch（无会话总线桌面会黑屏）
env DISPLAY=:1 dbus-launch startxfce4

# 3. 停止
anwind-x11-stop
```

也可以从 AnWind 桌面「开始菜单 → X11 桌面」直接打开窗口等待连接；
窗口控制条可切换分辨率（跟随窗口/固定）、唤起软键盘、一键真全屏
（返回键退出全屏）。

## 四、依赖说明（澄清常见误解）

**X 服务本体不依赖任何 pkg 包。** `CmdEntryPoint + libXlorie.so`
内置于 AnWind APK；XKB 键盘数据（源自 xkeyboard-config 2.48）fix9.10
起随 bootstrap 归档分发（归档内 `xkb/x11-xkb.tar.gz` 成员，三级容错
部署），首次启动自动解压，开箱即用；`termux-x11-nightly`
不是必需依赖（装不装都不影响内置 X11——装了也会被 debfix/anwind-x11
自动换回内置客户端，防止官方脚本经前缀重写后类名不存在导致的启动崩溃）。

需要通过 pkg 安装的只有「显示什么」：

| 组件 | 作用 | 安装命令 |
|------|------|---------|
| xfce4 + dbus | 完整桌面（推荐） | `pkg install x11-repo && pkg install xfce4 dbus` |
| openbox | 轻量窗口管理器 | `pkg install x11-repo && pkg install openbox` |
| xterm | 最小化验证 | `pkg install x11-repo && pkg install xterm` |

什么都没装时服务照常启动，只是没有可显示的窗口——终端会提示安装命令。
用 `anwind-x11 doctor` 可随时查看缺什么。

## 五、排障（anwind-x11 启动失败时）

启动全程写入 `$PREFIX/tmp/anwind-x11.log`（前置检查、自愈动作、
X 服务输出一站齐全）：

```sh
cat $PREFIX/tmp/anwind-x11.log   # 完整日志
tail -20 $PREFIX/tmp/anwind-x11.log
```

- 日志不会再出现“完全空白”：脚本第一行即写入启动横幅；X 服务在
  native 层静默失败（原因仅写 logcat）时，`anwind-x11` 会自动附带
  logcat 相关摘要。
- `anwind-x11 doctor`：逐项检查客户端/主副本/宿主 APK/
  libXlorie.so/app_process/XDG_RUNTIME_DIR 与桌面依赖，结论区直接给
  处理命令。
- 显示号 socket 被残留占用：先 `anwind-x11-stop` 再启动。
- `bin/termux-x11` 被官方包覆盖：启动时自动从 `etc/anwind/x11` 主副本
  恢复（日志中会记录恢复动作）。
- **libXlorie.so 加载失败**（logcat 见
  `dlopen failed: ...base.apk!/lib/...` 或 `UnsatisfiedLinkError`）：
  AnWind 以 useLegacyPackaging=true 打包，APK 内 lib 条目被压缩无法
  直接 dlopen，X 服务优先从 PM 解压目录（nativeLibraryDir）加载；
  若仍失败，`anwind-x11` 前置检查会直接提示 ABI 不匹配/安装不完整
  （建议安装 universal 包）。
- **Bootstrap 安装失败 / termux/x11-xkb.tar.gz**（fresh 安装首次启动
  终端全屏报错，9.7~9.9 实锤）：独立 XKB 资产在 CI 仓库管线中整文件
  丢失（*.tar.gz 在 git 提交/检出环节被吞，而 bootstrap *.zip 从未
  丢过），安装收尾对它的单点拷贝抛 FileNotFoundException → 整个
  bootstrap 安装被判失败 + revision 永不落盘（每次启动迁移重跑再
  失败）。fix9.10 根治：XKB 数据改随 bootstrap 归档分发
  （`xkb/x11-xkb.tar.gz` 成员，SHA 同步）+ 三级容错部署
  （bootstrap 内 → 独立资产 → 存量保留），任何来源缺失仅告警
  不阻断安装。已刷坏的设备：装 fix9.10+ APK 打开一次主界面即自动
  完成迁移与救援库部署。
- **XKB_CONFIG_ROOT is not set**（日志可见，X 服务随即
  System.exit(1)）：XKB 键盘数据缺失。fix9.10 起数据随 bootstrap
  归档分发（三级容错部署为 etc/anwind/x11/xkb.tar.gz，首次启动
  自动解压为 xkb/ 并导出 XKB_CONFIG_ROOT）；若仍提示缺失，打开一次
  AnWind 主界面重新部署，或 `pkg install xkeyboard-config`。
- **CANNOT LINK EXECUTABLE "…/dbus-daemon": library "libexpat.so.1"
  not found**（dbus-launch 尾随 "EOF in dbus-launch reading address
  from bus daemon"）：会话组件的 pkg 动态库缺失/损坏。fix9.9 排查
  实锤两个根因：① bootstrap 原包把 libexpat.so / libgpg-error.so
  以 dev 名入库且 SYMLINKS.txt 无 soname 条目 → libexpat.so.1 从
  不存在，而 dpkg status 已登记 installed → 依赖方永远不会再解包；
  ② 历史 dpkg 事故还可能整文件丢 liblz4.so.1（apt → libapt-pkg.so
  的依赖）→ pkg/apt 自身也 CANNOT LINK，连 pkg install 都无法自救。
  修复（rev20）：直接运行 `anwind-pkgfix`（离线补 soname 链接 +
  救援库三级兑底 + 逐二进制实跑验证，不依赖 pkg/网络/主界面，
  幂等）：优先用主界面部署的 etc/anwind/rescue 副本；副本也缺时
  v1.1 起直接从宿主 APK 内嵌 bootstrap 归档提取真身（ELF 魔数
  校验，历版 APK 均适用）；或 `anwind-x11`（会话预检失败时自动
  先跑一遍）；pkg 恢复后执行
  `pkg reinstall liblz4 libexpat libgpg-error && pkg upgrade` 把
  dpkg 数据库摆正防复发，再重跑 `anwind-x11 :1`。新装环境
  （bootstrap rev20 归档 + SHA 同步更新）不再含此缺陷。
- **窗口/画面已出但触摸无反应**（fix9.6 已修复）：旧版显示端把触摸
  事件整条吞掉未转发 X server（显示动不了/叉叉划不动）；升级到
  fix9.6 即恢复正常。
- **X11 窗口黑屏/画面空白**：多为桌面会话未起来——手动
  `startxfce4` 未带 dbus-launch 时无会话总线，xfwm/xfdesktop 起不来，
  根窗口呈黑色。请用 `env DISPLAY=:1 dbus-launch startxfce4` 或
  直接 `anwind-x11`（自动带 dbus-launch）；也可先 `anwind-x11 :1 xterm`
  验证 X 服务与显示链路本身是否正常。
- **连接状态**：X11 窗口未连接时会显示等待页与指引；若等待页长时间
  停在“正在连接”，运行 `anwind-x11 doctor` 并检查
  `$PREFIX/tmp/anwind-x11.log`。

## 七、已知边界

- X11 显示端建议 Android 8.0+（模块 minSdk 26；低版本设备终端功能不受影响）。

## 八、v2.22.3 fix10：分辨率握手 · z 盘 · 虚拟手柄 · 鼠标点击（本次修复）

### 8.1 X 屏幕分辨率真正跟随 `glibc-runner -d`

终端 → 窗口的**分辨率握手协议**（文件 `$PREFIX/tmp/.anwind-x11-res`）：

| 终端命令 | 写入内容 | X11 窗口行为 |
|----------|----------|--------------|
| `glibc-runner -d1280x720 game.exe` | `1280x720` | X 屏幕建为 1280x720，画面等比缩放进窗口（信箱居中） |
| `glibc-runner -d game.exe`（全屏） | `1280x720` | 同上（全屏默认桌面分辨率） |
| `glibc-runner game.exe`（窗口模式） | `native` | 跟随窗口（旧行为） |
| `anwind-x11`（桌面会话） | `native` | 跟随窗口（复位，避免游戏分辨率粘住桌面） |

实现：`X11ResolutionLink`（FileObserver 监听）→ 写 X11 偏好
（`displayResolutionMode=exact/native`）→ `LorieView.regenerate()` →
native `sendWindowChange` → X server RandR 调整屏幕尺寸。DXVK/游戏
从此按真实分辨率渲染（修复"游戏缩在左上角一小块"）。
控制条实时显示当前 X 分辨率（来自 glibc-runner 时高亮）。

### 8.2 wine z 盘永不为空（glibc-runner v3.2-anwind3）

- `glr_ensure_std_drives` 改用 `[ -e ]`（跟随链接）判定 —— **悬空盘符
  自动删除重建**（旧逻辑把悬空链接当"已存在"，z: 一旦失效永不修复）；
- `z:` 统一指向 `/`（wine 标准），根文件系统恒非空，天然覆盖 app 私有
  目录与 /sdcard；
- `--install-prefix` 与每次启动静默补齐路径同步修复；z: 创建不再依赖
  drive_c 存在。

### 8.3 虚拟手柄作用于 X11 界面

- 新增 `X11InputHub`（进程级单例）：WinHandler（UDP 7947，wine 侧
  winhandler.exe 对端）浮动窗口/全屏 Activity **共享单实例**，幂等启动；
- X11 桌面窗口叠加 Winlator 手柄层（`InputControlsView` + 触控板回落），
  控制条**"手柄"按钮一键开关**（profile 自动记忆/恢复）；
- `MainActivity.dispatchTouchEvent` 补上手柄触摸路由（原 fork 缺失，
  全屏模式点按钮也无反应）；
- 多指同时按住时松开一指不再误释放其它指（粘键/串键修复）。

### 8.4 触摸 → 真鼠标（SmartTouchBridge）

直注原生 X 触摸事件在 wine 下点不开文件/文件夹，且双击、落点都不可靠。
新的智能鼠标桥：

| 手势 | 动作 |
|------|------|
| 单指轻点 | 左键单击（按下即移动到指尖，落点零偏移） |
| 两次轻点 | **双击** —— 第二击自动吸附到第一击的 X 坐标（±450ms），wine 稳定识别 WM_LBUTTONDBLCLK，双击打开文件/夹 |
| 单指按住拖动 | 左键按住拖拽（移动 wine 窗口/滚动条） |
| 双指轻点 | 右键单击 |
| 双指滑动 | 滚轮 |

坐标变换：`视图像素 × (X屏幕/视图尺寸)`，固定分辨率模式下信箱等比、
无偏移。

### 8.5 部署说明

- 增强版 `glibc-runner`（v3.2-anwind3）已入库 `assets/termux/scripts/`；
  `TermuxBootstrapInstaller`（rev 22）部署主副本到 `etc/anwind/glibc-runner`
  并在缺失时落位 `bin/glibc-runner`；`anwind-glibc` 安装 glibc-runner 包后
  自动恢复增强版（防 pkg 覆盖）。
- 存量设备手工更新：把 `glibc-runner` 覆盖到
  `/data/data/com.anwind/files/usr/bin/glibc-runner` 并
  `chmod 700` 即可。
